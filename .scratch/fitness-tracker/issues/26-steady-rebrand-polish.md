# Steady rebrand, saved meals, add-food order, weight tenths, human touch

Status: resolved
Type: feature batch + rebrand (2026-07-16)

User feedback round: weight showing whole pounds, photo-of-food buried,
wanted saved meals, asked whether backfilled days count toward the
streak (they already do — streak is recomputed from data, documented in
README), alternate app icons not working, and a rebrand away from "75".

## Resolution

Weight tenths — the only whole-pound displays were goal weight
(dashboard Goal card + Weight chart annotation): now
`.precision(.fractionLength(0...1))`. Day-view weight field gets the
same explicit format.

Add Food order — Photo of Food promoted to a second full-width gradient
button (foodTint→photoTint) directly under Describe Your Meal via a
shared `headlineLabel`; removed from the fallback list. Order: Describe
→ Photo → Saved Meals → Quick Log → other ways.

Saved meals — `Shared/SavedMeal.swift`: `SavedMeal` + `SavedMealItem`
(@Model, additive schema — registered in PersistenceController; facts
stored as Codable NutritionFacts since it's a new entity). "Save as
Meal" button on every meal screen (alert name prompt, success haptic);
"Saved Meals" section in Add Food logs every item into the selected
meal in one tap, swipe-to-delete.

Backwards compatibility — all schema changes this batch and last are
additive (new entities, defaulted properties); SwiftData lightweight-
migrates in place. Bundle ID, App Group, store URL, URL scheme all
unchanged.

Rebrand "75" → **Steady** — display name (app + widgets) via
INFOPLIST_KEY_CFBundleDisplayName; Siri phrases use `.applicationName`
so they follow automatically. Dashboard monogram → trendline mark
(chart.line.downtrend.xyaxis on the theme gradient) + time-of-day
greeting + daily-rotating encouragement line computed from real stats
(lbs down, streak, consistency; falls back to warm generic lines).
Monthly Wrapped plate + "Made with Steady"; CalendarSync note. Repo,
project, targets, bundle ID deliberately still "75".

Alternate icons fixed — root cause: manual CFBundleIcons dict in
-5-Info.plist declared alternates for iPhone only; the merged plist's
CFBundleIcons~ipad had no CFBundleAlternateIcons (app targets iPad), and
loose-PNG alternates are the legacy fragile path. Replaced with asset-
catalog alternates: new 1024 px Steady icons (descending trendline +
endpoint dot on each palette gradient; primary adds dark + tinted
variants) generated by a CoreGraphics script; appiconsets
Icon-Ocean/Sunset/Violet/Rose;
`ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES = "Icon-Ocean Icon-Sunset
Icon-Violet Icon-Rose"` on both app configs. Verified the built plist
now carries CFBundleAlternateIcons under BOTH CFBundleIcons and
CFBundleIcons~ipad. Legacy Resources/AltIcons + plist dict removed;
Settings picker now surfaces setAlternateIconName errors instead of
failing silently.

Build: ** BUILD SUCCEEDED **; merged Info.plist verified
(CFBundleDisplayName = Steady, alternates present for both device
families).
